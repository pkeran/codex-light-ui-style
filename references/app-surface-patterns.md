# App Surface Patterns

Use this file when the user wants the style to scale across multiple app contexts rather than a single isolated component.

## Overview Dashboard / Workbench Home

- Treat the page as an operational summary, not a marketing hero
- Lead with one strong summary surface, then secondary cards
- Use calm status emphasis and minimal decorative treatment
- Keep metrics and next actions readable within one scan

## List / Detail Workbench

- Prefer clear primary list surfaces with restrained row hover states
- Use drawers, side panels, or detail panes as bright structured surfaces
- Let borders and spacing separate concerns more than shadows
- Toolbars should remain quiet; the data is the main actor

## Settings / Configuration

- Group related controls into clear cards or sections
- Avoid making settings screens look heavier than workbench screens
- Use helper text sparingly and keep it functional
- Rely on alignment and spacing to create trust

## History / Logs / Activity Streams

- Use slightly denser spacing while preserving legibility
- Keep severity and state indicators obvious but restrained
- Avoid turning rows into colorful status bars unless the data truly needs that emphasis
- Let metadata stay secondary and scannable

## Forms / Wizards / Data Entry

- Keep primary fields on bright neutral surfaces
- Focus states should be crisp, not glowing
- Error states should be clear, calm, and local
- If there are steps, use pale-blue active states rather than loud progress chrome

## Drawer / Inspector / Secondary Panels

- These surfaces may use slightly stronger elevation than normal cards
- Preserve the same border and radius family as the rest of the system
- Keep content modular and vertically grouped
- Avoid style drift into “floating glass palette” territory

## Empty States / Zero States

- Use a small icon, a direct heading, one sentence of context, and one next action
- Keep the tone operational
- Do not turn empty states into feature promotion sections

## Cross-Surface Rule

Across all app surfaces:

- blue stays an emphasis color
- cards stay mostly white
- borders stay structurally important
- gradients stay in the background layer
- active states stay clear without becoming luminous
